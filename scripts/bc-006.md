# BC-006 local runner

Use a checkout containing the accepted BC-006 implementation and its `.venv`.
Commands below run from the repository root. `review` is offline; `run` requires
a clean exact approved revision and checks Ruff, pytest and diff first.

## Offline exact packet

```bash
.venv/bin/python -m governed_agent_runtime.bc006_runner review \
  --output /tmp/bc-006-pre-run-packet.json
```

The target must not already exist. No Ollama request, preload or model inference
is made. The two scripted paths test the environment/runtime, not model quality.

## Approval and one Qwen trajectory

After reviewing the exact generated packet, record the human disposition in a
copy of `reports/reviews/bc-006-materials/approval-template.json` outside the repo:
`APPROVED`, exact `git rev-parse HEAD`, packet SHA, reviewer and review time.
This pre-run disposition does not authorize individual writes: the terminal
asks separately for each exact synthetic action with a unique confirmation ID.

```bash
.venv/bin/python -m governed_agent_runtime.bc006_runner run \
  --provider ollama \
  --user-id anton \
  --approval /home/anton/projects/evidence/governed-agent-runtime/bc-006-approval.json \
  --output /home/anton/projects/evidence/governed-agent-runtime/bc-006/run-001
```

The unique output directory must not exist. No retries or tuning. Ollama version,
model digest and D1 sampling settings are fixed in the packet. No preload: loading
cost is retained in provider metadata. Every request uses the same system message
and a new self-contained user context, never provider conversation history.

After each admitted write proposal, inspect the printed target, parameters,
evidence, risks and verification. Type exactly `CONFIRM <shown-ID>` to authorize
that one mock action. Any other response stops. Do not give the model corrective
advice through the terminal. Confirmation expires after 300 real seconds.

Raw responses (including thinking), exact requests, input hashes, observations,
confirmation events, counters and outcomes are saved. A failed run remains saved;
never rerun into the same directory. Stop/timeout is not permission to retry.

## Manual proposal transport (reserved alternative)

Use the same `run` command with `--provider manual` and a metadata file:

```json
{
  "model_identity": "fill actual model and reasoning setting",
  "environment": "fill actual session/client environment",
  "independent_session_per_call": true
}
```

Pass its path through `--manual-metadata`. For each step the runner writes a
`.prompt.txt` containing the system instruction plus exact context. Use a **new,
independent external model session** without this repository/chat history. Manual
clients may render the system instruction as ordinary text; record this provider
role/environment difference rather than claiming equivalence to Ollama.

Save a response wrapper containing the printed input SHA and the **entire unchanged
response text**, properly JSON-escaped:

```json
{
  "input_sha256": "the exact SHA printed by the runner",
  "raw_response": "the model's exact returned JSON text as a JSON string"
}
```

Supply its path at the terminal prompt. Do not remove fences, edit decisions,
repair JSON or retry an answer: invalid/stale import stops and is preserved.
This is a transport route, not approval for a second measured trajectory.
