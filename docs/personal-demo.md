# Личная демонстрация

Локальный показ синтетического payment-api с реальной моделью. Это не запуск
измеренного эксперимента и не подключение публичного сайта к станции.

## Один раз после установки или обновления

В корне отдельного checkout проекта с установленными зависимостями `[dev,live]`:

```bash
.venv/bin/python -m governed_agent_runtime.personal_demo --prepare
```

После подготовки установить короткую команду и локальный README:

```bash
.venv/bin/python -m governed_agent_runtime.personal_demo --install
```

Далее из любой папки WSL:

```bash
~/.local/gov-agent-local/run
```

Установщик сохраняет предыдущий gar-local с суффиксом backup, заменяет ссылку
run и создаёт README в корне единой папки. Старый README исследования,
на который раньше вела ссылка, остаётся на месте. Существующие ссылки results,
simulator и service-state не перемещаются: results по-прежнему ведёт к старым
исследовательским пакетам, а временные данные показа находятся отдельно ниже.

Открыть папку в проводнике Windows:

```bash
explorer.exe "$(wslpath -w "$HOME/.local/gov-agent-local")"
```

Нужны Node/npm и локальная Ollama с моделью/версией из
[`live-model-profile.json`](../specs/core/live-model-profile.json).
Подготовка устанавливает UI-зависимости и собирает UI, но не вызывает модель.
Проверки разработки выполняются отдельно до принятия версии, не перед показом.

## Быстрый запуск

```bash
.venv/bin/python -m governed_agent_runtime.personal_demo
```

На вопрос терминала ответить `yes`, `y` или `да` в любом регистре.
Убедиться, что WebUI и другие клиенты не отправляют запросы к Ollama.
Непонятный ввод повторяет вопрос; Enter без ответа отменяет запуск.
Никакие JSON-файлы редактировать не нужно.

После сообщения о готовности сервера открыть http://127.0.0.1:8001.
Второй локальный вход с готовыми запросами — http://127.0.0.1:8000.
Одна подготовка принадлежит одному входу; runtime сохраняет подтверждения
действий, проверки условий, бюджеты шагов/диалога и сроки ожидания.
Лимита в две подготовки нет. Существующие пределы числа сессий/сценариев
в памяти остаются; если они достигнуты, завершить сервер и запустить снова.

Остановка — Ctrl+C в терминале. Закрытие браузера не завершает сервер.
Следующий запуск не повторяет старый запрос. Если остановлен процесс во время
обращения к модели, следующий запуск может предложить перезапуск Ollama.
Это отдельное подтверждение: перезапуск прервёт запросы других клиентов.
Восстановление использует системную службу `ollama` в Linux/WSL с systemd;
может потребоваться пароль sudo. Другие способы размещения провайдера этим
восстановлением не поддерживаются. При отказе или ошибке запуск закрыт.

Обычный старт проверяет готовую сборку и метаданные провайдера, но не запускает
тесты, сборку, скачивание модели или inference. Холодная загрузка модели после
начала сценария по-прежнему занимает время; мгновенный ответ не обещается.

## Данные

Временные записи личного показа находятся в
`~/.local/state/gar-personal-demo/session-*`. Они нужны текущему UI и диагностике,
не являются принятым evidence. После штатного завершения записи удаляются.
После прерывания оставшиеся сессии удаляются при следующем успешном восстановлении
под общим замком. Во время показа можно сохранить скриншот интересного результата.
Записи могут содержать личный текст; не публиковать автоматически.

Общее служебное состояние остаётся в
`~/.local/state/governed-agent-runtime/ollama-coordinator`:
оно предотвращает одновременный запуск личного показа и исследовательского сервера.
Маркер неизвестного завершения не удаляется без подтверждённого восстановления.
Учёт старых допусков и исследовательские пакеты не очищаются этим запуском.
Минимальные архивные маркеры восстановления не содержат запросов и сохраняются.

Строгий исследовательский запуск остаётся отдельным:
[`local-ui-simulator.md`](local-ui-simulator.md). Он требует своего дизайна,
допуска и сохранения результатов. Параметры и evidence экспериментов не меняются
ради удобства личного показа.
